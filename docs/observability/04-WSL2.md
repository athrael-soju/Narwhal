# Monitor a WSL2 development fleet

In this setup the fleet runs in WSL2 on your workstation, and Prometheus and Grafana run on a homelab machine. Two SSH tunnels connect them: one lets the homelab scrape the fleet, and the other lets your Windows browser reach Grafana.

You get the same **Narwhal Orchestrator** dashboard and `narwhal-router` and `engines` jobs as a full deployment.

## Before you start

- `homelab` has to work as an SSH host from both WSL2 and Windows. Run `ssh homelab true` in each to check.
- Start the fleet with `narwhal dev up` and confirm it with `narwhal dev verify`.
- The homelab needs the same [prerequisites](01-Start-and-Verify.md#before-you-start) as a router host: Linux, Docker Engine with the Compose plugin, Python 3.11 or newer, and `curl`.

The examples assume the four-engine [RTX 5090 reference](../dev/08-RTX-5090-Reference.md) fleet in the default instance directory, `runs/dev`, and a Narwhal checkout at `~/projects/Narwhal` on the homelab. With a different engine count, forward one port per engine and expect one scrape series per engine plus the router.

## Copy the fleet document

From WSL2:

```bash
dev_run=$(python -c 'import json; print(json.load(open("runs/dev/lifecycle.json"))["run"])')
ssh homelab 'mkdir -p ~/projects/Narwhal/runs/workstation'
scp "$dev_run/fleet.json" homelab:projects/Narwhal/runs/workstation/fleet.json
```

## Let the homelab scrape WSL2

The fleet only listens on loopback inside WSL2, so the homelab can't reach it directly. Open reverse tunnels for the router and engine ports and keep this running for as long as the fleet is up:

```bash
ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -R 127.0.0.1:18000:127.0.0.1:18000 \
  -R 127.0.0.1:18101:127.0.0.1:18101 \
  -R 127.0.0.1:18102:127.0.0.1:18102 \
  -R 127.0.0.1:18103:127.0.0.1:18103 \
  -R 127.0.0.1:18104:127.0.0.1:18104 \
  homelab
```

These are the default router port and the four engine ports. If you ran `dev init --port-base`, use your ports instead. If another SSH or VS Code forward already holds one of these ports on the homelab, pick a free one there. Then change the matching engine `url` in the copied `fleet.json` (or `NARWHAL_ROUTER_URL`, for the router) to that port, because Prometheus scrapes the addresses listed there.

## Open Grafana from Windows

In PowerShell, open a second tunnel for your browser:

```powershell
ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 `
  -L 127.0.0.1:33000:127.0.0.1:3000 `
  -L 127.0.0.1:39090:127.0.0.1:9090 homelab
```

## Start monitoring on the homelab

From the homelab checkout:

```bash
NARWHAL_FLEET=runs/workstation/fleet.json \
NARWHAL_ROUTER_URL=http://127.0.0.1:18000 \
make observe
```

If a monitoring stack is already running there, you don't have to restart it. Regenerate its target files instead, writing them into the directory Prometheus mounts for discovery:

```bash
prometheus_targets=/path/to/prometheus/targets
.venv/bin/python -m tools.observability.make_targets \
  runs/workstation/fleet.json \
  --router-url http://127.0.0.1:18000 \
  --output-dir "$prometheus_targets"
```

Prometheus notices the new files by itself. Each engine entry carries an `iid` label, which the dashboard uses to match engines to their roles.

## Check that it works

On the homelab:

```bash
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=up{job=~"narwhal-router|engines"}'
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=narwhal_router_ready{job="narwhal-router"}'
```

You should see five scrape series (the router plus four engines), all at `1`, and router readiness at `1`.

Then open `http://127.0.0.1:33000/d/narwhal-router/narwhal-orchestrator` in your Windows browser, pick the current router, and send a few requests through Narwhal. The request and token panels should start moving, and you should see four engine rows along with pool assignments and role history.

## Shut down

Run `narwhal dev down`, then close both SSH tunnels. The homelab keeps the metrics it collected.
