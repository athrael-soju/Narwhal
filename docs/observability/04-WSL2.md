# Monitor a WSL2 development fleet

Prometheus and Grafana run on the monitoring host at SSH destination `homelab`. WSL2 forwards router and engine metrics to it. The Narwhal Orchestrator dashboard shows the `narwhal-router` and `engines` jobs.

## Prerequisites

- `ssh homelab true` succeeds from both WSL2 and Windows.
- A WSL2 fleet started with `narwhal dev up` passes `narwhal dev verify`.
- The homelab has a Narwhal checkout at `~/projects/Narwhal`.

## Connect metrics and dashboard ports

1. Copy the fleet file from WSL2 to the homelab checkout:

    ```bash
    dev_run=$(python -c 'import json; print(json.load(open("runs/dev/lifecycle.json"))["run"])')
    ssh homelab 'mkdir -p ~/projects/Narwhal/runs/workstation'
    scp "$dev_run/fleet.json" homelab:projects/Narwhal/runs/workstation/fleet.json
    ```

2. Open the reverse tunnel from WSL2 for the fleet's lifetime. For a custom `dev init --port-base`, change these ports to match:

    ```bash
    ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
      -R 127.0.0.1:18000:127.0.0.1:18000 \
      -R 127.0.0.1:18101:127.0.0.1:18101 \
      -R 127.0.0.1:18102:127.0.0.1:18102 \
      -R 127.0.0.1:18103:127.0.0.1:18103 \
      -R 127.0.0.1:18104:127.0.0.1:18104 \
      homelab
    ```

3. Open a separate browser tunnel from Windows PowerShell:

    ```powershell
    ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 `
      -L 127.0.0.1:33000:127.0.0.1:3000 `
      -L 127.0.0.1:39090:127.0.0.1:9090 homelab
    ```

## Start or update the monitoring stack

Start a new stack from the homelab checkout:

```bash
NARWHAL_FLEET=runs/workstation/fleet.json \
NARWHAL_ROUTER_URL=http://127.0.0.1:18000 \
make observe
```

Regenerate a running stack's router and engine target files in its mounted discovery directory (`prometheus_targets`):

```bash
prometheus_targets=/path/to/prometheus/targets
.venv/bin/python -m tools.observability.make_targets \
  runs/workstation/fleet.json \
  --router-url http://127.0.0.1:18000 \
  --output-dir "$prometheus_targets"
```

Prometheus reloads the targets automatically. Keep the `iid` labels from the fleet configuration.

## Check scrapes and routed activity

Query Prometheus from the homelab:

```bash
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=up{job=~"narwhal-router|engines"}'
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=narwhal_router_ready{job="narwhal-router"}'
```

| Query | Expected result |
| --- | --- |
| First (`up`) | Five healthy series: the router and four engines |
| Second (`narwhal_router_ready`) | `1` |

Check routed traffic:

1. Open `http://127.0.0.1:33000/d/narwhal-router/narwhal-orchestrator` in a Windows browser.
2. Select the current router.
3. Send a few requests through Narwhal.
4. Check the request and token panels, the four engine rows, pool assignments, and role history.

## Stop the fleet

The homelab stack keeps its collected history when the fleet stops.

1. Run `narwhal dev down` in WSL2.
2. Close both SSH tunnels.
