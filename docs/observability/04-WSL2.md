# Monitoring a WSL2 development fleet

## Prerequisites

- `monitor` is the SSH alias of the Prometheus and Grafana monitoring host.
- `ssh monitor true` succeeds from both WSL2 and Windows.
- A WSL2 fleet started with `narwhal dev up` passes `narwhal dev verify`.
- The monitoring host has a Narwhal checkout at `~/projects/Narwhal`.

## Connecting metrics and dashboard ports

| Port | Template default | With `narwhal dev init --port-base P` |
| --- | --- | --- |
| Router | `18000` | `P` |
| Engine HTTP | `18101` upward, one per engine | `P+1` upward |

1. Copy the fleet file from WSL2 to the monitoring host's checkout:

    ```bash
    dev_run=$(python -c 'import json; print(json.load(open("runs/dev/lifecycle.json"))["run"])')
    ssh monitor 'mkdir -p ~/projects/Narwhal/runs/workstation'
    scp "$dev_run/fleet.json" monitor:projects/Narwhal/runs/workstation/fleet.json
    ```

2. Open the reverse tunnel from WSL2 for the router port and the four engine HTTP ports:

    ```bash
    ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
      -R 127.0.0.1:18000:127.0.0.1:18000 \
      -R 127.0.0.1:18101:127.0.0.1:18101 \
      -R 127.0.0.1:18102:127.0.0.1:18102 \
      -R 127.0.0.1:18103:127.0.0.1:18103 \
      -R 127.0.0.1:18104:127.0.0.1:18104 \
      monitor
    ```

3. Open the browser tunnel from Windows PowerShell:

    ```powershell
    ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 `
      -L 127.0.0.1:33000:127.0.0.1:3000 `
      -L 127.0.0.1:39090:127.0.0.1:9090 monitor
    ```

## Starting or updating the monitoring stack

Start a new stack from the monitoring host's checkout:

```bash
NARWHAL_FLEET=runs/workstation/fleet.json \
NARWHAL_ROUTER_URL=http://127.0.0.1:18000 \
make observe
```

Regenerate the router and engine target files of a running stack from the monitoring host's checkout:

```bash
.venv/bin/python -m tools.observability.make_targets \
  runs/workstation/fleet.json \
  --router-url http://127.0.0.1:18000 \
  --output-dir runs/observability/mounts/prometheus/targets
```

## Checking scrapes and routed activity

Query Prometheus from the monitoring host:

```bash
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=up{job=~"narwhal-router|engines"}'
curl -fsSG http://127.0.0.1:9090/api/v1/query \
  --data-urlencode 'query=narwhal_router_ready{job="narwhal-router"}'
```

| Query | Expected result |
| --- | --- |
| First (`up`) | Five healthy series: the router and four engines |
| Second (`narwhal_router_ready`) | `1` |

Check routed traffic:

1. Open `http://127.0.0.1:33000/d/narwhal-router/narwhal-orchestrator` in a Windows browser.
2. Select the current router.
3. Send requests through Narwhal.
4. Check these panels:
    - **Request outcomes** and **Token throughput**
    - The four rows of the engine table
    - **Pool assignments**
    - **Engine role history**

## Stopping the fleet

1. Run `narwhal dev down` in WSL2.
2. Close both SSH tunnels.
